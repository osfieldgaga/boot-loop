# Boot Loop deployment — Render Free

Selected by the PM October 11. One Node web service serves the game, `/dev`, matchmaking and WebSockets. No separate frontend host, database or paid service is needed for this configuration.

## Configure the service

Upload the project to a Git repository that Render can access. Keep `.env`, `.aws`, `.codex`, `node_modules` and local build archives out of it. Connect that repository in Render and create a Blueprint using the root `render.yaml`, or create a Web Service with these exact settings:

| Setting | Value |
| --- | --- |
| Runtime | Node |
| Instance plan | **Free** |
| Region | Ohio (US) |
| Root directory | Repository root |
| Build command | `npm ci --include=dev && npm run check` |
| Start command | `npm start` |
| Health check | `/health` |
| Node version | `24.13.0` |
| Environment | `NODE_ENV=production` |
| Automatic deploys | Off; deploy approved releases manually |

Leave `VITE_SERVER_URL` unset: the client uses the same origin. Render supplies `PORT`; the server binds `0.0.0.0`. Do not enable multiple instances: room state is in memory in one process. The project has no accounts, secrets or database credentials to configure.

After deploy, record the actual `https://…onrender.com` URL in submission.md and Sprint 6. Visit `/health` and `/release.json`; their build IDs must match. Open `/`, create a room, copy the invite, join from another device/network, complete Timed and Stock matches, then rematch. Test `/dev` separately. Run the SDK checks with `BOOT_LOOP_URL` set to the Render origin.

## Free-plan limits

Render's documentation says free web services sleep after 15 idle minutes and take about a minute to restart. The loading screen belongs to Render before our application starts. A fixed URL is available, but immediate availability through judging is not guaranteed. Free service quotas and restrictions still apply. PM must review a cold start and this limitation in Sprint 6 T6. No paid upgrade is authorized.

Any server restart/redeploy clears existing rooms; old invitations expire. Finish test matches before deploying and create new rooms afterward. Matches do not reconnect or resume. Clients should return to practice with clear connection feedback.

## Restore a previous release

Keep the source/build archive and checksum generated by `node tools/release-bundle.mjs`. For rollback, redeploy a previously verified commit in Render (or restore that archive into the source repository and deploy it). Review `/health` and `/release.json`, then create/join/rematch again. This restores code, not active rooms. Deploy both shared server and client together.

The optional Dockerfile provides the same single-service layout. It has not been executed here because the local Docker daemon is unavailable; native Render deployment is the selected path.
