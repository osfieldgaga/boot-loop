## Marking results

- Mark `- [x] Pass` after you review an item successfully.
- Mark `- [x] Skip` and write a reason when you decide it is no longer relevant.
- Leave both unchecked for failed or untested work and describe the issue.
- Use the Comments and changes section to change scope or carry work forward.
- Final acceptance is yours. The assistant does not check your testing or acceptance boxes.
- Actual checkbox interactivity depends on the Markdown editor; editing `[ ]` to `[x]` works in any text editor.

Dates are targets. Movement and dash feel require explicit approval. Optional features can be skipped; missing contest requirements cannot be waived by this checklist. October 28 is the submission target; October 29–30 is contingency time.
